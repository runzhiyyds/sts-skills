# Solve2Ship Skills v0.2.0 — Headless engine bridge / 无前端引擎连接

## English

Adds an optional stdlib HTTP client for an already installed local STS engine.
Default status/list/show are read-only. Hash-reviewed task saving, explicit paid
exploration/retests, cancellation, private review packets/user-answer submission,
final-review closure and accepted source-ZIP download use actual engine APIs.
No frontend is required. The helper never installs resources, reads a model profile,
creates/increases a budget, executes generated code or invents operator acceptance.

Loopback-only destinations, no proxy/redirect forwarding, bounded JSON/archives,
owner-only operation receipts and uncertain-submission fencing are covered by local
HTTP protocol tests. Operator answer files must carry actual explicit attestation;
identity and semantic truth are not certified. Download checks the existing accepted
final quality gate and receipt's SHA256, refuses overwrite and never runs the archive.
Saved successful receipts recover without HTTP even after resources are exhausted;
unresolved/refused submissions stay fenced. Known deterministic final execution
requires explicit operator-review intent but no model allowance. Full readiness/review
commands target STS v0.14; older engines can be inspected without assuming readiness.

31 stdlib tests pass (20 new bridge protocol tests plus11 existing utility tests).
These are protocol fixtures, not business optimization evidence. The initial
independent service forward-test scope remains documented separately.

Actual installed-package check on 2026-11-10: the ZIP was unpacked outside both
repositories and run with a minimal Python environment against local STS v0.14.
Chinese status, a closed four-case final-review packet and download of an accepted
Rules source-service ZIP all worked; the downloaded SHA256 matched the engine
receipt. The owner had explicitly accepted those four frozen outputs. That is
self-attested operator feedback, not measured general accuracy. This bridge check
submitted no votes, made no model calls, changed no resources and did not execute
the downloaded service. It does not prove arbitrary task success or fresh-engine setup.

## 简体中文

新增可选的本机 STS 真实接口连接工具，无需前端。默认状态/列表/结果只读；任务预览与
哈希审阅保存、明确启动/重测/取消、私有复核包与用户答案提交、最终复核关闭及已验收
服务 ZIP 下载均调用引擎接口。不自动安装资源、读密钥、创建或提高预算、执行生成代码，
也不代用户生成认可意见。

仅连接本机，禁用代理与重定向，有界读取、私有持久回执与不确定请求防重提交均有协议
测试。复核只提交用户真实判断；自我声明不代表身份或语义真值已核验。下载核验既有
质量门禁与验收回执 SHA256、不覆盖旧文件、不执行源码包。成功回执在资源耗尽后仍可
零 HTTP 恢复；未知或拒绝的提交仍禁止重放。已知确定性方案的最终检查须明确人工复核，
无需模型额度。完整就绪/复核接口面向 STS v0.14；旧引擎可只读查看，不能默认为已就绪。
31 项测试通过，其中20项为新增桥接协议测试，
其余11项为原辅助工具测试；这些不能冒充业务优化结果。

2026-11-10 还进行了真实安装包验证：在两个仓库之外解压 ZIP，使用最小 Python 环境
连接本机 STS v0.14，中文状态、4 条已关闭的最终复核材料和已验收规则服务包下载均
可用，下载 SHA256 与引擎回执一致。所有者已明确接受这4条冻结输出；这是自我声明
的人工意见，不是普遍准确率。此次连接验证没有提交判断、调用模型、改变资源或执行
下载的服务，不能证明任意业务任务或全新引擎安装已经成功。
